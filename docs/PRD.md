# Career Knowledge Copilot - 产品需求文档（PRD）

## 1. 产品概述

Career Knowledge Copilot 是给正在找实习的大学生使用的求职资料知识库助手。用户把岗位 JD、面试题和项目材料上传为 PDF 后，可以集中查看和删除资料，并针对这些资料提问。系统的回答必须标出来源文件名和页码，让用户能回到原文核对信息。

这里的“知识库”指系统把 PDF 内容按小段保存并建立检索索引，提问时先找出相关小段，再让大模型依据这些小段作答；它不是自动联网搜索。

## 2. 用户与问题

**目标用户**：正在准备实习或校招，需要保存多个岗位 JD、面试资料和项目资料的大学生。

**典型问题**：

- JD 分散在多个 PDF，难以快速比较岗位要求。
- 面试复习时记不住资料中的知识点和出处。
- 项目资料较多，回答“我的项目用了什么技术”时需要反复翻找。

## 3. MVP 目标与成功标准

MVP（最小可行产品）只验证“上传资料后能得到可信、可追溯回答”这一核心闭环。

| 目标 | 可验收标准 |
| --- | --- |
| 集中管理资料 | 用户可以看到已上传 PDF 的名称、大小、上传时间和处理状态，并可删除。 |
| 资料问答 | 用户可输入问题，系统只依据已成功处理的资料回答。 |
| 可核对性 | 每个有事实依据的回答至少含一条“文件名，第 N 页”引用。 |
| 基础连续对话 | 同一浏览器会话中，刷新后仍可看到已保存的提问与回答。 |

## 4. MVP 功能范围

### 4.1 上传 PDF

- 页面提供文件选择和上传按钮。
- 仅接受 `.pdf` 文件，单文件最大 20 MB；一次上传一个文件。
- 上传完成后显示“处理中”；解析、切分和建立向量索引完成后显示“可提问”。
- 同名文件可以上传，但系统以文件 ID 区分；前端应提示用户可能重复。
- 无法读取或没有可提取文字的 PDF 显示“处理失败”和简短原因。

### 4.2 文档列表与删除

- 文档列表展示文件名、文件大小、上传时间、状态和删除入口。
- 删除前二次确认。
- 删除成功后，文档原文件、检索片段和关联引用均不可再用于回答。

### 4.3 基于文档提问

- 用户输入自然语言问题并发送。
- 后端检索最相关的文档片段，再调用大模型生成中文回答。
- 回答区展示正文和引用；引用格式为 `文件名，第 3 页`，可点击定位至文档详情或下载入口（MVP 可以先仅展示文字引用）。
- 没有足够依据时，回答“在已上传资料中没有找到足够依据”，不得编造答案或引用。

### 4.4 基础对话记录

- 首次进入问答页时创建一个对话；后续提问保存到该对话。
- 刷新页面后恢复该对话中的消息和引用。
- MVP 只要求保存当前浏览器的一条最近对话，不提供多会话管理界面。

## 5. 暂时不做（明确非目标）

- 不做登录、注册、找回密码和用户账号。
- 不做 OCR：扫描件或图片型 PDF 不在 MVP 支持范围内。
- 不做 Agent：系统不拆解任务、不调用外部工具、不自动执行多步骤任务。
- 不做支付、订阅、用量计费或优惠券。
- 不做复杂权限、多人协作、团队空间、文档共享或角色管理。
- 不做 Word、图片、网页、音视频等 PDF 以外的文件格式。
- 不做在线编辑 PDF、自动生成简历、自动投递、联网搜索和岗位推荐。

## 6. 关键页面与交互

| 页面 | 用户可做什么 | 必须显示什么 |
| --- | --- | --- |
| 文档页 | 上传、查看、删除 PDF | 文件列表、状态、失败原因、删除确认框 |
| 问答页 | 输入问题、查看历史、查看引用 | 消息列表、发送状态、回答正文、文件名和页码 |

## 7. 业务规则与边界

- 只有状态为“可提问”的文档片段可参与检索。
- 回答引用来自检索到的片段，页码必须为原始 PDF 的页码（从 1 开始）。
- 一个回答可含多条引用；同一文件同一页只显示一次。
- 大模型或检索服务失败时，保存用户问题，展示“暂时无法生成回答，请重试”，且不伪造回答。
- 删除文档不会删除历史对话文本，但历史引用应标记为“原文件已删除”。

## 8. MVP 验收边界

产品负责人按 `docs/test-cases.md` 验收。上线前至少保证：上传、处理、列表、删除、提问、引用、历史记录和异常提示均可走通一次。
